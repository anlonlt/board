Board: you take over as the orchestrator on Claude Code web (or any computer where the previous orchestrator is gone). Everything you need is in git: the board (`board-mirror`), the step prompts (`docs/prompts/`), each part's work (its branch). Talk to the owner in en, in this chat (the phone board points at the computer, which may be off).

1. **Be on the kit's branch:** `git branch --show-current` must be `cli-agnostic` (the branch with `.kit/`). If not: `git fetch origin cli-agnostic && git checkout cli-agnostic`. The kit's hooks only run when the session started on that branch; if they don't (no `BOARD:` line at the start), do by hand what they would: `python3 -I .kit/kit.py step start|complete <post>` after each task change, and `python3 -I .kit/web_takeover.py save` before you stop.
2. **Board up, plan back:** `python3 -I .kit/web_takeover.py`. It starts the board from git and prints `kit.py resume` plus the steps to continue, each with its branch and prompt.
3. **Your task list:** one TaskCreate per open step, subject "<PART> <title>", metadata {"train": "<train>", "part": "<PART>"} (the existing post is adopted, never duplicated); TaskUpdate in_progress for each one you continue.
4. **Continue the crashed steps:** each as its own part, a subagent (Agent tool, worktree isolation when available; else one after the other) with the continuation prompt the script printed. The cloud has no device cap. A part pushes its branch and writes its result in its post (`kit.py done`); you check each Done (bars met, tests run) before you mark it complete.
5. **Then the planned steps**, in train order, the same way, each from its prompt `docs/prompts/<post>.md` on a branch `<part>` from `cli-agnostic`.
6. **Keep git current:** after each step change and before you stop, `python3 -I .kit/web_takeover.py save` (the board) and push every branch with work. If a push is refused, say exactly which, in one line, to the owner.
7. **Hand back:** when the owner is back on the computer, `board` there, then `python3 -I .kit/kit.py receive` brings what you wrote on the board (via `board-mirror`) into the computer's board; the parts' branches are on GitHub. Say in one line what ran, what is done, what waits.
